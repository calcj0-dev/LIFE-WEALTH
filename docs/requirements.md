# ゲーム開発 要件定義書

このファイルを要件定義書の正とする（claude.ai 上のドキュメントは古い版）。

2026-10-18 · @Sho

## 概要

LIFE & WEALTH は、投資とライフイベントを体験しながら資産形成を楽しく学べる、Webベースの人生シミュレーションボードゲームです。

| 項目 | 内容 |
| --- | --- |
| ゲーム名 | LIFE & WEALTH |
| ジャンル | 人生シミュレーションボードゲーム（Web） |
| コンセプト | 投資とリアルな出費を体験しながら、楽しく資産形成を学べる |
| 体験できる投資 | 株式（業種別）・投資信託・国債・ゴールド（インカムゲイン、キャピタルゲイン、複利効果、積み立て）、住宅の購入。投資の落とし穴（詐欺、流行りに飛びつく、借金して投資）も体験する。投資用の不動産は将来の検討事項 |
| ライフイベント | 子どもの教育費などのリアルな出費 |
| 主要ターゲット | NISA・FIRE・資産形成に関心のある層、マネー教育や投資体験ゲームを楽しみたい層 |
| 開発体制 | 1人で開発。プログラム、UI、素材、金額の調査は基本的に Claude が作成し、本人が確認・判断する |
| 開発目的 | 多くの人に遊んでもらうことを中心にする（遊びやすさ、分かりやすさ、宣伝のしやすさを重視）。将来は広告や一部有料化で収益化する |

## スコープ

最初のリリースは、コアとなる遊びが最後まで通して遊べる最小構成（MVP）に絞ることを案とします。

| 項目 | 内容 |
| --- | --- |
| 対象プラットフォーム | Webブラウザ（PC とスマートフォン。スマートフォンは横向き） |
| プレイ人数 | 1人用。将来は CPU のライバル2人と競う（プロトタイプでは作らない）。対戦は将来追加 |
| MVPに含めるもの | コアループ、タイトル画面、結果画面、基本設定 |
| 対象外（初回） | 税金やNISA・iDeCoなどの制度、広告・課金、ランキングサーバー、多言語対応 |

公開は無料で行います。ユーザー数が増えたら、広告や一部有料化を検討します。

## 機能要件

1ターン＝1ヶ月。最初に遊ぶ年数（10・20・30・40・50年、最初の設定は20年）を選び、最後の純資産で競います。20年（240ターン）で30分前後を目安にします（段階3.5で変更）。

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| F-01 | コアループ | 1ターン＝1ヶ月。ルーレットで盤面を進み、1年ごとにニュースと決算、取引タイムがある。年齢は扱わず「○年目」で数える | 必須 |
| F-02 | 勝敗判定 | 最後の純資産で競う。CPU がいない間は、最後まで遊んだら終わり。詳細は design.md の 9章 | 必須 |
| F-03 | 相場モデル | 株式（業種別）・投資信託・国債・ゴールド・住宅の価格を、過去の平均利回りと値動きに寄せた乱数で毎月少しずつ動かし、年末のニュースで大きく動かす。税金は扱わない | 必須 |
| F-04 | ライフイベント | 結婚・出産（ルーレットで決まる）・教育費、住宅購入・住宅ローン、転職・昇給・失業、病気・事故・介護 | 必須 |
| F-05 | タイトル画面 | 開始、続きから、設定 | 必須 |
| F-06 | ゲーム画面 | ボード、所持資産、年齢、家計の表示 | 必須 |
| F-07 | 結果画面 | 純資産と資産推移の振り返り、リトライ | 必須 |
| F-08 | 操作 | マウス／タッチ | 必須 |
| F-09 | セーブ／ロード | 途中でやめても続きから遊べる | 推奨 |
| F-10 | 設定 | 音量、画面表示 | 推奨 |
| F-11 | サウンド | BGMと効果音 | 推奨 |
| F-12 | チュートリアル | 初回プレイ時の遊び方説明 | 任意 |
| F-13 | コース選択 | FIREコース、億万長者コースなど、勝利条件が変わるコースを選べる | 将来 |
| F-14 | 対戦 | CPU のライバル2人、複数人プレイ | 将来 |
| F-15 | 収益化 | ユーザー数に応じて広告、一部有料化 | 将来 |

## 非機能要件

数値は一般的な目安です。プラットフォームが決まったら見直します。

| 分類 | 要件（案） |
| --- | --- |
| 性能 | 標準的な端末で 60fps を目標、起動からタイトル表示まで 5 秒以内 |
| 対応環境 | 未定（OS、ブラウザ、画面解像度・縦横） |
| データ保存 | ローカル保存。異常終了してもセーブデータが壊れないこと |
| アクセシビリティ | 文字サイズ変更、色覚多様性に配慮した配色、操作の割り当て変更 |
| 言語 | 日本語。あとから他の言語を足せる作りにする（design.md 11.1） |
| 品質 | リリース前に致命的な不具合（進行不能・クラッシュ）ゼロ |

## 技術要件

技術は TypeScript + React（Vite）に決定しました。人生ゲーム風のボードは SVG とアニメーション部品で描き、他の画面と切り離した部品にして、後から Phaser に差し替えられるようにします。

| 役割 | 使うもの |
| --- | --- |
| 画面全体・資産表・グラフ | React |
| プログラムの言語 | TypeScript |
| 開発中の動作確認と公開用ファイルの作成 | Vite |
| ボード・ルーレット・駒の動き | SVG + アニメーション部品（将来 Phaser に差し替え可） |

検討した選択肢は次のとおりです。

| 選択肢 | メリット | デメリット |
| --- | --- | --- |
| TypeScript + React（推奨） | 表・グラフ・フォームが作りやすい。グラフやUIの部品が豊富。スマホ対応がしやすい。利用者が多く、Claude も正確に書きやすい | 駒の移動や派手な演出は自前で作る必要があり、ゲームらしさは出しにくい |
| TypeScript + Phaser | 2Dゲーム専用エンジン。アニメーション、効果音、シーン管理が標準で使える | 表やグラフ、文字入力などのUIが苦手で手間がかかる。画面サイズへの対応も自分で調整が必要 |
| React + Phaser の組み合わせ | ボード部分は Phaser、資産表やメニューは React と、得意な方で作れる | 二つの仕組みをつなぐ必要があり、構成が複雑になる |
| TypeScript + Vue または Svelte | React と同じくUIが作りやすく、書く量が少し少ない | React より部品や情報が少ない。演出面の弱さは React と同じ |
| Unity（WebGL書き出し） | 本格的なゲーム用エンジンで演出も強い。将来スマホアプリにも出しやすい | 読み込みが重く、スマホのブラウザでは動作が不安定。エディタの操作は本人が行う必要があり、Claude に任せる部分が減る |
| Godot（Web書き出し） | 無料・軽量のゲームエンジン。2Dに強い | Unity と同じくエディタ操作が必要。Web版は一部のブラウザで制約がある |

どれを選んでも、公開は GitHub Pages など無料のホスティングでできます。

リポジトリ運用（案）:

- GitHub の calcj0-dev/LIFE-WEALTH で管理し、main を常に動く状態に保つ
- 機能ごとにブランチを切り、プルリクエストで main に取り込む
- 画像や音声など大きいファイルは Git LFS を検討

## スケジュールとマイルストーン

完成時期は決めず、次のフェーズの順に少しずつ作っていきます。

1. 企画: コンセプトとこの要件定義書を確定する
2. プロトタイプ: 仮素材でコアループだけを作り、面白いか確かめる
3. アルファ: MVPの全機能を実装する
4. ベータ: 素材を差し替え、テストプレイと不具合修正を行う
5. リリース: 公開し、反応を集める
